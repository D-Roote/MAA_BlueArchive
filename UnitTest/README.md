# UnitTest

Windows에서 가상환경을 준비한 뒤 저장소 루트에서 실행합니다.

```powershell
.venv/Scripts/python.exe -m unittest discover -s UnitTest -v
```

게임 실행, Tasker 수명주기, 최소화, 작업 목록 및 설정 UI의 회귀를 검증합니다. 게임 실행·캡처·입력 API는 모의 객체로 대체하고 Qt는 offscreen 모드로 사용하므로 실제 게임을 실행하거나 조작하지 않습니다.

`test_pipeline_defaults.py`는 설치된 MaaFramework SDK로 프로젝트 리소스를 실제 로드하고 Pipeline v2 기본값의 상속·노드별 덮어쓰기를 확인합니다. 전체 파이프라인(백업 JSON 포함)에 `LongPress`가 남아 있지 않은지, `Click`의 좌표·오프셋이 유지되고 `duration`이 없는지도 검사합니다. 캡처·인식 실행·입력 동작은 수행하지 않습니다. 기준 문서는 [MaaFramework 5.12.3 Pipeline Protocol](https://github.com/MaaXYZ/MaaFramework/blob/v5.12.3/docs/en_us/3.1-PipelineProtocol.md)입니다.

연결 진단은 선언된 Win32/Adb 프리셋 필터, 프로그램/PID 확인, ADB 경로·주소, 두 UI 동기화, 중복 요청 차단, 실행/종료 전 연결 해제를 검증합니다.
화면은 단발/선택 FPS, BGR 색상·데이터 소유권·표시 비율, 느린 요청 중첩 방지, 접기/페이지 변경/일시적 오류에서 연속 유지 및 수동 중지/실제 연결 해제/종료 시 중지를 검증합니다. `test_runtime_preview.py`는 실행 중 캐시 읽기만 수행하여 컨트롤러 생성/캡처/입력/inactive/창 스타일·투명도 변경이 없는지, 재연결 대상의 읽기 전용 식별 정보, 준비 대기·실제 대상 종료, 중지 후 SDK inactive와 원래 창 상태 복원의 순서 및 복원 실패 재시도를 검증합니다. 진단 연결은 지원되는 PostMessage 입력 방식으로 만들지만 실제 입력 요청은 보내지 않습니다.
연속 표시의 상태·버튼·카드 크기 고정과 이미지 캔버스 전용 다시 그리기도 Qt 이벤트로 확인합니다. 세로 분할은 실제 마우스 드래그, 최소 높이 제한, 모든 카드 순서, 펼친 영역 확장, 이미지 자동 확대, 높이 비율 저장/복원을 검증합니다.
`test_monitor_fps.py`는 새 이미지가 실제로 그려진 횟수만 집계하고 중복 repaint/합쳐진 업데이트는 제외하는지 확인합니다. 목표/출력 FPS 표시, 절댓값 기준(max(1, ceil(목표/4))) 경계값, 목표 1~15에서 출력 0/미달/초과에도 경고 억제, 15 초과에서 경고 적용, 기호·퍼센트 없는 경고 문구, 실제 경과 시간, 경고 복구, 초기 측정 및 중지 시 측정 타이머 정리를 검증합니다.
설정의 연결 정렬, Select의 포커스 잔류 강조 제거, 15/30/45/60 FPS 저장도 확인합니다. 창/최대화/좌우 폭/카드 펼침 복원, 지연 저장·종료 시 저장, 잘못된 UI 값 처리 및 자동 실행 방지도 검증합니다. offscreen 화면보다 큰 창은 Qt가 복원 시 위치/크기를 보정할 수 있습니다.
실제 창/ADB의 연결 성공, 캡처 방식별 게임 화면, 실효 FPS 및 장시간 SDK 안정성은 이 모의 테스트가 보장하지 않습니다.

`test_after_actions.py`는 완료 후 동작의 중앙 정렬·배타 선택·모두 해제, 영구 저장/이번에만 복원, 정상 완료 및 중지·실패·닫기 억제, 실행 스냅샷, 중복 콜백을 검증합니다. HWND/PID/실행 경로 재확인과 강제 종료 없는 Windows API 요청, 권한 복원·실패 처리, MAA 종료 후 도우미의 프로세스 핸들 대기/실패 기록도 모의 객체로 검증합니다. 실제 프로그램 종료·잠금·절전·최대 절전·시스템 종료 및 전원 도우미 실행은 테스트하지 않습니다.
컨트롤러별 종료 UI 전환·리소스 허용 목록·Adb만 선언한 경우, 앱 종료 강제 선택·옵션 보존·미구현 ADB 명령 억제도 검증합니다. 체크박스 정렬은 실제 캡처한 텍스트 픽셀 영역으로 밝은/어두운 테마를 검사하며, 텍스트 클릭/스페이스 키 동작을 함께 확인합니다. 현재 ADB 앱/에뮬레이터 종료는 UI 및 선택 저장만 구현되어 있습니다.

UI 테스트는 시작 화면의 구분선·외곽 여백, 밝은/어두운 테마의 경로 입력칸·버튼 정렬, 창 크기별 가로 스크롤 발생 여부를 확인합니다. 설정 탐색은 부분적으로 보이는 최상단 카드, 스크롤 끝, 스크롤이 없는 화면, 직접 클릭한 항목의 선택 유지를 구분해 검증합니다. 자동 실행 작업의 제거·복원과 실행별 로그 초기화 설정의 기본값·저장·적용도 함께 검증합니다.

최소화 테스트는 게임 창에 한 번만 `WM_SYSCOMMAND / SC_MINIMIZE`를 전달하는지, 전송 실패/창 종료/전경 잔류 시 정상적으로 실패하는지, 이후 사용자 복구를 다시 최소화하지 않는지 확인합니다.

표준 PI v2 기본 Win32 구성도 파일로 읽어 검증합니다. `window_regex`, 상대 리소스 경로 목록, 임의의 `task.entry`로 실행하며, `PrintWindow`/`FramePool`과 최소화 설정을 조합합니다. 내장 게임 실행 작업, Agent, 별도 `program` 설정, Pipeline의 `focus`는 최소화 기능의 필수 조건이 아닙니다.

현재 런타임은 PI 전체를 구현한 범용 클라이언트는 아닙니다. Win32 `window_regex`가 필요하며 첫 번째 리소스를 사용합니다. `class_regex`만을 사용하는 검색, `import`, `attach_resource_path`, Agent/pretask 선언 등의 처리를 보장하지 않습니다. 기본 구성 테스트 통과를 PI 전체 호환 또는 다른 게임의 실제 최소화·캡처 성공으로 해석하지 않습니다.

스펙 기준: [MaaFramework 5.12.3 Project Interface V2](https://github.com/MaaXYZ/MaaFramework/blob/v5.12.3/docs/en_us/3.3-ProjectInterfaceV2.md).
